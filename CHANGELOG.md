# v1.3.0

- Feat: New 'deleteAll' method to delete all rows of a table.

- Feat: 'Find' and 'Select' methods can now receive an offset parameter.

- Feat: New 'dropUnknownColumns' option on MariaDBConnection.

- Feat: New 'timezone' option on MariaDBConnection, defaults to 'local', use 'auto' to set the session timezone to the Node.js one so dates generated by the database (CURRENT_TIMESTAMP) are converted correctly when the server uses a different timezone.

- Fix: Connections not being released back to the pool when a query fails or when a table is created by 'createOrUpdateTable'.

- Fix: Only the first field being validated on 'Create', 'Update' and 'Upsert'.

- Fix: 'Update' (and 'Create'/'Upsert' on MariaDB < 10.5) returning the wrong row.

- Fix: Foreign key constraint names colliding between tables, they are now named `<table>_<column>_fk`.

- Fix: Filters with null values being refused on non boolean/timestamp fields.

- Fix: IN and BETWEEN filters always being refused and generating invalid SQL.

- Fix: Falsy defaults (0, false, '') being ignored and 'CURRENT_TIMESTAMP()' being inserted as text.

- Fix: Identifiers not being escaped on 'Upsert', RETURNING, 'Count' and table creation/update.

- Fix: Empty queries on 'Find', 'Select' and 'Count' generating invalid SQL.

- Fix: 'createOrUpdateTable' altering unchanged columns on every startup.

- Fix: 'Count' returning BigInt and DECIMAL fields returning strings.

- Fix: TIMESTAMP fields without maxSize being created as TIMESTAMP(1) and NOT NULL TIMESTAMP fields receiving an implicit ON UPDATE CURRENT_TIMESTAMP on servers with explicit_defaults_for_timestamp disabled.

- Fix: Empty strings being treated as null on non-null fields.

- Fix: Wrong error message on invalid limit.

- Fix: Connection passed to DatabaseManager constructor causing an unhandled rejection on connection errors and being silently ignored when a 'default' connection already exists.

- Fix: Concurrent calls to 'connect' on MariaDBConnection resolving before the connection is established.

- Fix: 'disconnect' called while connecting leaving the pool open.

- Fix: SQL injection through the 'orderBy' direction on 'Find' and 'Select'.

- Fix: 'Upsert' overwriting fields not provided on data with NULL when the row is duplicated, by default only the provided fields are updated now.

- Fix: 'Upsert' with an empty updateFields not returning an empty array when the row is duplicated, as documented.

- Fix: 'Upsert' not validating non nullable fields before inserting.

- Fix: Foreign key changes not being atomic, they are now applied on the same ALTER TABLE as the other changes, alternating the constraint name between `<table>_<column>_fk` and `<table>_<column>_fk2`.

- Fix: Integer columns being created too small when maxSize is a power of 2, and SINT/DECIMAL columns ignoring minSize, existing columns are widened on the next startup.

- Fix: maxSize and minSize not being validated on STRING fields.

- Fix: Explicit null on nullable fields with a default being replaced by the default.

- Fix: 'Find', 'FindOne' and 'FindByID' not validating the query fields, values and orderBy, 'FindByID' now also accepts numeric ids.

- Fix: 'Update' on tables without a primary key not returning the updated row when the database changes a column (ON UPDATE CURRENT_TIMESTAMP) or rounds a DECIMAL/TIMESTAMP value.

- Fix: 'UpdateWhere' with only auto increment fields generating invalid SQL.

- Fix: 'Create' refusing an empty object even when every non nullable field has a default.

- Fix: BIGINT and insert ids silently losing precision, an error is now thrown when they can't be safely converted to a number.

- Fix: Prepared statements being created for every 'Create', 'Update' and 'Upsert' call.

- BREAKING: DatabaseManager constructor now throws when a different connection is already registered as 'default'.

- BREAKING: Columns that don't exist on the model are no longer dropped by default, set 'dropUnknownColumns' to true to keep the old behavior.

- BREAKING: 'Delete', 'DeleteWhere', 'Update' and 'UpdateWhere' now refuse empty filters, use 'deleteAll' to delete all rows.

- BREAKING(types): 'Upsert' return type is now `Record<string, unknown> | []`, matching the empty array returned when the row is duplicated and ignored, use `Array.isArray` on the result before accessing its fields.
  - This is a typing only change, the runtime behavior is the one already documented.

# v1.2.3

- Deps: Bumped MariaDB dependency to fix a vulnerability in the MariaDB driver.

# v1.2.2

- Fix: Wrong data return behavior on 'Create' and 'Upsert' methods due to different versions of MariaDB.

- Fix: Incorrectly checking of MariaDB's version, that caused misbehavior on major versions of MariaDB equal or superior to 11 if the minor version was less than 5.

- Fix(typo): Improved non-null check message, fixed orthography and added more context to the error.

# v1.2.1

- Feat: New 'Count' method that allows the counting of how many rows are in a table, how many not null columns, distinct values of a column and set a custom name for the count key in the result object.

- Fix(types): Fix typing mistake that caused an regression forcing an object to be passed to 'Find', calling this method without any argument will behave the same way as passing an empty object.
  - This is a typing only mistake, that doesn't change how the method behave or parse its parameters.
